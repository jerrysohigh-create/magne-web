安全不是一堵牆。是三道門。

主系統、簽章與復原被分開設計。即使其中一層面對風險，其他層仍保有自己的邊界。

01 / INTENT應用提出請求

App 或 DApp 發起簽章、身份或安全資料操作，不直接接觸安全元件。

02 / AUTHORIZE系統先做授權

Android 權限、使用者確認與 OMAPI 存取規則共同判斷呼叫方。

03 / ROUTE標準服務路由

Secure Element Service 將受控 APDU 交給 HED NFC 供應商服務。

04 / EXECUTEN60 內部執行

請求經 eSE1 進入 N60；密鑰、隨機數與加密操作留在硬件邊界內。

05 / RETURN只返回結果

Android 與應用只取得簽章或受控結果，私鑰本體不被匯出。

PARALLEL ANDROID SECURITYKeystore2 → KeyMint → Hardware-backed key operations

Keystore2 與 KeyMint 是 Android 的並行硬件金鑰服務。它們與 OMAPI / eSE 路徑共同構成 MAG1 的系統安全層，但本圖不把 KeyMint 錯畫成 N60 內部模組。

SYSTEM FEATUREandroid.hardware.nfc.ese

Android 宣告內嵌安全元件能力，NFC 堆疊可識別 eSE 路徑。

OMAPI FEATUREandroid.hardware.se.omapi.ese

系統提供標準 OMAPI eSE 介面，應用不直接接觸底層硬件總線。

ANDROID SERVICEsecure_element · ISecureElementService

Secure Element Service 已註冊並由 Android 安全元件框架管理。

LIVE TERMINALeSE1 · mIsConnected:true

實機回報 eSE1 終端在線，安全元件通道處於連接狀態。

KEY SERVICESKeyMint · Keystore2

硬件金鑰服務與 Android Keystore2 同時存在，承接金鑰生命週期與受控操作。

ACCESS CONTROLAPDU RULES · FILTERS PRESENT

實機返回逐應用存取與 APDU 過濾狀態；具體規則、雜湊與識別資料不公開。

證據邊界：ADB 無法保證直接讀出安全元件的完整商業型號；N60 型號來自 MAG1 已確認的產品整合，ADB 則驗證 HED、OMAPI、eSE1 與 Android 安全服務確實運行。本頁不披露其他安全芯片料號。

III

安全因素 · CHIP ARCHITECTURE

三個安全因素，
三條不能混淆的路徑。

L1UTEE

把敏感流程放進可信執行邊界。

L2HYPERSEED N60

以安全元件保存密鑰並完成簽章。

L3HYPERSEED 72B

以獨立 NFC 晶片保存復原路徑。

L1 / UTEE

可信執行環境

Normal World 與 Secure World 以 TrustZone 邊界分離，敏感 API、密鑰服務與安全儲存只在可信側完成。

讀圖摘要 Normal World TrustZone Secure World

一般系統可以發起請求，但敏感 API、密鑰服務與安全儲存留在可信執行邊界內。

L2 / N60

安全元件簽章

NFC Controller 與 eSE 以受控通道連接。密鑰儲存、隨機數、加密加速與防拆偵測收斂在安全元件內。

讀圖摘要 NFCC SWP eSE

NFC 通訊與安全元件分工，簽章、密鑰、隨機數與防拆偵測收斂在硬件安全邊界。

L3 / 72B

NFC 復原晶片

獨立安全處理器負責離線復原材料。它不替主系統背書，只保存一條可被授權喚回的所有權路徑。

讀圖摘要 Secure Core NFC RF Recovery Payload

復原資料走獨立晶片路徑，讓裝置遺失、主系統失效與所有權復原保持分離。

IV

威脅路徑 · THREAT PATHS

風險會走捷徑。
架構不能。

事件被保護的邊界系統回應
一般系統遭到攻擊TEE / 安全元件

敏感簽章操作與密鑰仍在隔離硬件路徑內。

裝置遺失或損壞離線復原

以獨立 NFC 復原材料重建所有權路徑。

雲端服務不可用端側能力

本地金庫與硬件簽章不以雲端可用性為前提。

惡意應用請求簽章使用者確認

簽章路徑與應用請求分離，讓授權發生在受控邊界。

認證範圍說明：CC EAL2+ 與 CC EAL6+ 為對應組件、模組或評估範圍的認證參考，不代表整機或所有商業配置取得相同等級認證。
