How to read evidence

  • Device metadata identifies what the system reports; it is not a hardware performance or certification test.
  • Static code shows implemented paths and declared configurations; it does not prove successful operation.
  • Historical tests apply to their recorded firmware, app, date and conditions only.
  • Project statements remain attributed specifications. Conflicting developer-build observations are listed for reconciliation, not silently substituted.
  • Pending means no adequate evidence or test yet; it does not automatically mean unsupported or defective.

MAGNE Wallet: versions, networks and safe preparation

Confirmed: package identity, static function paths and current platform services. Not confirmed: creation/import/recovery success, per-chain transfers, signing behavior or compatibility with arbitrary cards and DApps. Static analysis found unresolved security issues. USER and USERDEBUG 1.2.15 share the relevant code; changing the signature alone is not a fix. SE participation does not make the whole Android app a trusted environment. No user-data leak or remote asset theft was demonstrated. Engineering fixes and asset-free re-testing are required before a production-use judgment.

Hardware, ports, buttons and package contents

  • The sample reports a 12 GB RAM class; Linux exposes about 11.14 GiB. Approximately 6.91 GiB of zram is compressed swap, not extra physical RAM.
  • The storage device identifies as WDC SDINFDO4-512G and reports UFS 3.1. Its main block device is about 512.083 GB; /data is about 464.00 GiB before considering used space. These are different units and allocation layers, not a throughput benchmark.
  • The display interface reports 1080 × 2388 and 60/120 Hz modes. The 60 Hz snapshot does not remove the separately observed 120 Hz mode. HDR types are declared capabilities, not measured brightness or certification.
  • This sample has no verified Type-C display output or working ToF ranging. A VL53L0 device object is unbound; the DP transmitter and PTN38003A redriver nodes are disabled. Node presence is not an accessory compatibility result.
  • UMP9620 audio-codec binding supersedes the inference from the legacy sc2730 sound-card name. The wireless-charger names CPS4021/CPS4201 differ and still require BOM confirmation. Exact component models are not substituted for functional tests.

USB file transfer, charging and tethering

  • The unchanged cable/host connection negotiated USB High-Speed: 480 Mbit/s bus signaling, not measured file-copy speed. The controller’s super-speed-plus limit does not prove the external port supports that speed.
  • The connected phone was a data device and power sink. Dual-role/OTG and audio-accessory declarations are present, but USB drives, reverse power and analog adapters were not tested.
  • Local PD revision is 3.0. The driver reported a fixed 5 V / 3 A profile (15 W nominal); this is neither measured absorbed power nor the phone’s maximum charging rating. PPS was not selected or tested.
  • No display was attached. Local DP Alternate Mode registration does not prove a negotiated video link; DP transmitter/redriver nodes are disabled on this build. Do not buy a display adapter on this evidence alone.

Wired charging, wireless charging and battery care

  • On the sampled full battery, the PD node reported 5 V / 3 A while generic power nodes reported 5 V / 2 A. These layers must not be combined into a measured charging result; no external power meter or maximum-power test was used.
  • The fuel-gauge design/full fields both report 4841 mAh. This is a driver estimate/configuration, not a discharge capacity test and not a replacement for the project’s 5000 mAh / up to 33 W wired / 15 W wireless specification. Vendor reconciliation is pending.
  • The raw cycle-count field is not interpretable without the vendor’s unit definition. No battery-health percentage, wireless-charge success or PPS performance has been verified.

Camera, photos, videos and modes

  • MAG1WW60-1, camera 1.0000.19: the recorded test saved one 4080 × 3072 JPEG and a 31.89 s, 1920 × 1080 H.264 video at about 30 fps. Complete file decoding and device/computer hashes passed. Front/rear previews switched successfully; no front photo was saved.
  • A later 16 October capture confirmed More → Ultra res and a 6144 × 8064 image (49.55MP) before adding the Frame watermark. The earlier 12.53MP sample alone did not establish this mode. Front-camera driver naming and public output dimensions likewise describe different layers.
  • A camera-app freezer/Binder exit occurred before the successful capture. It is a recorded issue for investigation, not proof that a sensor or AI algorithm failed. Long recordings, 4K/HDR/EIS combinations, night/portrait/macro and image-quality improvement remain untested here.

Local call translation and the system voice assistant

  • On MAG1WW60-1 with AI app 15.00001.22, a translation tile was temporarily added for a consented automated-service test call. It was absent from the initial Quick Settings layout, so this is not evidence that every user can find it there by default.
  • Enabling translation was followed by increasing NPU task counts; the llm_service process held /dev/vha0 and mapped the Qwen2.5-1.5B model. The user confirmed translation output. This supports NPU use in that tested call-translation path.
  • The second run added 15,121 completed driver tasks including tail work, with no driver failures in its samples. Task counts are not tokens and accumulated execution time is not translation latency.

MAG1WW60-1 local AI

MAG1WW60-1 integrates dedicated camera visual-AI components and a separate local call-translation model path. The camera application and JN1 configuration contain scene-recognition, denoising, depth/segmentation and beauty components. Integration does not establish that every component executes in every mode.

In the MAG1WW60-1 call-translation test, the Qwen2.5-1.5B model service opened the NPU device and completed task counts increased after translation was enabled. This supports NPU use by that translation path. A subsequent DEMO produced new transcripts and translations with Wi-Fi and mobile data disabled; see the recorded test conditions below. The processor used by each ASR/TTS stage was not established.

Camera mode-by-mode runtime tracing remains pending. There is no current evidence that ordinary photography uses the translation language model, or that CPU, GPU and NPU simultaneously execute the same model.

NFC, tapping cards and wallet recovery limits

  • HED NFC and SE services exist, but an external NFC backup card, the embedded SE and the platform TEE have distinct roles. No card model, backup/restore operation, lockout policy or cross-device recovery was validated in this report.
  • The wallet app handles decrypted recovery phrases during display/backup. Do not describe NFC backup as proof that recovery phrases never enter Android. Use only vendor-confirmed cards and wait for the analyzed build’s security fixes and recovery verification.
