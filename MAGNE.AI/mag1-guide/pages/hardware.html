前置條件

  • 取出手機及包裝清單
  • 保持介面乾燥
  • 不要用取卡針探測麥克風孔

操作參考 · 實測範圍見下方

  1. 先核對包裝標籤中的型號 MA1 / 產品 MAG1 與訂單。不要公開 IMEI 或序列號。
  2. 觀察 USB-C 介面、3.5mm 耳機孔、SIM 卡槽、攝像頭與側邊按鍵；確切方位待機身圖示註複核，勿按推測插針。
  3. 對照包裝清單記錄手機、線材、充電器、卡針及 NFC 配件是否實際隨箱提供；官網功能描述不等於每批包裝均贈送該配件。
  4. 按機身圖示識別電源與音量鍵；短按、長按、組合鍵的本機行為需分別核驗。
  5. 首次使用前移除運輸保護物，檢查玻璃、介面和配件是否損壞；破損時聯絡銷售渠道。

CPU / GPU / NPU — 偵測資訊與運行證據

證據採集於 2026-10-16，適用 MAG1WW60-1 開發軟體版本（系統版本 MAG1WW60-1）。頻率表、驅動讀值與應用實際執行分開說明。

處理單元偵測資訊如何解讀
CPU8 核心、3 個 cpufreq 策略組。CPU0–3：2.184 GHz；CPU4–6：2.301 GHz；CPU7：2.704 GHz。調速器：uscfreq。以上為驅動 cpuinfo_max 回報的頻率上限，不代表所有核心持續同時達到該頻率，也不是效能跑分。
GPUMali-G57；OpenGL ES 3.2。綁定驅動：mali。devfreq 回報檔位：384 / 512 / 680 / 850 MHz。初始掃描採樣為 384 MHz；後續通話翻譯測試採到 384、680、850 MHz。畫面渲染同樣使用 GPU，不能據此證明 AI 在 GPU 執行。
NPU設備樹標識：img,ax3xxx-nna；綁定驅動：ax3xxx-nna。回報檔位：307.2 / 384 / 500 / 614.4 / 768 / 1000 MHz。通話翻譯的 177 個樣本中，devfreq cur_freq / target_freq 均為 307.2 MHz；debugfs core_freq_khz 則維持 30000，兩者不一致，實體時鐘口徑待廠商釐清。1 GHz 是列出的檔位，不是量測到的運行峰值。

NPU 已實際執行甚麼？

本地通話翻譯已取得 NPU 實際執行證據：啟用翻譯後驅動任務計數增加，LLM 服務同時開啟 /dev/vha0 並映射 Qwen2.5-1.5B-Instruct-UNI 模型，使用者確認有翻譯結果。第二輪連同尾部運算新增 15,121 個完成任務；任務數不是 token 數，累計執行時間也不是使用者感知延遲。

初次驅動檢測未隔離網際網路；後續 10086 DEMO 在關閉 Wi-Fi 與行動數據後仍產生新的中文識別及英文譯文，支持該次本地翻譯路徑。這不代表已實測 TOPS、tokens/s、校準 NPU 時鐘、GPU AI 運算或同一模型的 CPU／GPU／NPU 協同執行。CPU 架構與 GPU 核心數現另引述上方產品單頁。 查看實測 DEMO →

SE — 安全元件、錢包介面與核驗範圍

證據日期：2026-10-16；MAG1WW60-1 開發軟體版本，系統版本 MAG1WW60-1；錢包 USERDEBUG 1.2.15。下列服務觀察與靜態程式碼結果，不等於錢包交易已完成驗收。

項目已有證據解讀與限制
SE 連線狀態系統掃描回報 eSE1 的 mIsConnected=true；Android OMAPI ISecureElementService / com.android.se 與 android.hardware.secure_element@1.2-service.hed 均在運行。可確認回報的連線狀態與服務鏈，不能當作每項錢包操作成功的證明。HAL 介面版本 1.2 不是 COS 版本。
錢包整合應用使用 Android OMAPI SEService / Reader / Session / Channel，並包含 HED OSU SDK（OSU-SDK-1.2.3）。靜態程式碼包含 PIN 驗證、種子／助記詞生成與匯入、公鑰讀取及簽名路徑。本次稽核未執行 APDU、建立／匯入錢包或簽名廣播交易。
COS 與 AppletSDK 提供 COS 版本查詢、升級與恢復 API；錢包程式碼引用種子及幣種 Applet。尚未查詢當前 COS 版本及已安裝 Applet 清單。APK 中有介面，不代表已確認晶片韌體狀態或安全屬性。
晶片精確規格已有 HED 服務名稱及 hednfc 綁定等整合證據。SE 精確料號、CPU 架構、實體主頻、記憶體容量及 EAL 認證仍待核實。沒有對應廠商證據前，不將 CIU98M50、SC300 或 120 MHz 寫成本機已偵測規格。
TEE 與 PIN 保護另一條平台 TEE 路徑回報 Unisoc Trusty v2.1.1。錢包程式碼透過 AndroidKeyStore 請求使用者認證及 AES/GCM，以保護保存的 PIN。Trusty v2.1.1 不是 SE 的 COS 版本。尚未驗證該把密鑰的 securityLevel 與硬體保護層級；不能將整個 Android 錢包說成在 TEE 中執行。
StrongBox 與 NFC 備份檢查的系統特性清單未宣告 StrongBox；NFC 備份使用另一張外部卡片。未宣告 StrongBox 不等於沒有 SE，也不能據此確定某把 Keystore 密鑰的位置。外部備份卡、內嵌 SE 與平台 TEE 是不同元件。

在錢包中的分工

程式碼中的錢包簽名路徑：Android 構造及確認交易 → OMAPI / HED SE HAL → 內嵌 SE 與錢包 Applet → Android 組裝及廣播簽名交易。PIN 保護則使用另一條 AndroidKeyStore / KeyMint 平台服務路徑。

目前應用在顯示、匯入及備份路徑會處理助記詞明文，因此不能宣稱「助記詞從不離開安全晶片」。本次也未證實 SE 獨立可信交易顯示，或私鑰不可匯出的完整保證。SE 服務可用不等於 Android 應用已通過安全驗收；開發版的審閱狀態另見錢包章節。

待廠商補充：對應料號／BOM 與認證適用範圍、COS 與 Applet 版本、密鑰匯出邊界、PIN 錯誤重試及鎖定機制、韌體驗簽與反回滾，以及可信輸入／顯示設計。本節不公開裝置序列號、APDU 內容、PIN、助記詞或私鑰。
